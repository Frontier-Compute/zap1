what this is for

Receipts for work that machines claim to have done.

Automated systems report what they did, and those reports are normally trust-me claims: a dashboard number an outsider cannot recompute. A ZAP1 receipt is the same claim in checkable form.

a

Agent actions

Agents commit hash-only receipts of registrations, policies, and actions. The tree carries live AGENT_ACTION leaves today; the worked example below is one of them.

b

Evaluation verdicts

A published Inspect AI hook (inspect-receipts on PyPI) emits hash-only receipts of evaluation outcomes, with an offline checker that returns MATCH or MISMATCH.

c

Lifecycle and payment facts

Machine ownership, deployments, hosting payments, and paid-access events become receipts a counterparty can verify without seeing books, keys, or customer rows.

Verify a live receipt in under a minute, without trusting this server:

curl -s https://api.frontiercompute.cash/verify/41792a315c4942da8901d1fd9c12e2598c47ec0e40f3086e2c883ee9c70ead17/proof.json -o proof.json
python verify_proof.py --proof proof.json

Expected result: VERIFIED. Count-bound proof is valid. Leaf is included in the published root. The verifier script ships at the repo root and re-walks the proof locally.

Scope, stated plainly The proof checks inclusion against the published root. That root's next on-chain anchor is pending; prior anchors are listed at /anchor/history. A receipt proves the claim was committed and never changed, not that the claim is true.
how the proof moves

The review path is short on purpose.

This page is generated by the ZAP1 API and pulls aggregate counts from the same database that serves /stats.

01

Commit an event

Applications create typed lifecycle events without publishing private rows or raw customer data.

02

Hash the leaf

ZAP1 commits event material into BLAKE2b leaf hashes with stable type semantics.

03

Anchor the root

Published roots bind the leaf count and are anchored to Zcash mainnet in ZAP1 structured memos. Anchor txids are published for independent lookup.

04

Publish proofs

Proof bundles expose inclusion material, anchor metadata, and machine-readable verifier input.

05

Verify offline

The zap1-verify crate and verify_proof.py re-walk proofs without trusting the hosted UI. Independent Python, Rust, and TypeScript verifiers are held byte-identical by a CI-gated equivalence corpus.
